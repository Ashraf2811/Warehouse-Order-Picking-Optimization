# Warehouse Order Picking Efficiency Optimization

A Streamlit dashboard for the final **V3.1 Proximity-Constrained Wave Optimization** results from the Warehouse Order Picking Efficiency Optimization project.

## What this application does

The application presents the final optimized warehouse waves generated by the project notebook.

It provides:

- Overall optimization KPIs
- Recommended wave workload analysis
- Workload and utilization distributions
- Spatial-spread analysis
- Recommended wave filtering and exploration
- Warehouse-location assignment analysis
- 2D warehouse-position visualization
- CSV previews
- Downloadable filtered results

The Streamlit application **does not rerun the optimization model**. It reads the final CSV outputs generated by the notebook.

## Final project results

The final V3.1 optimization in the notebook reports:

| Metric | Result |
|---|---:|
| Recommended waves | 8,189 |
| Average workload | 23.40 units/wave |
| Average utilization | 93.58% |
| Average unique locations | 2.07/wave |
| Average spatial spread | 8.18 |
| 95th percentile spatial spread | 34 |
| Coordinate-valid assigned units | 191,583 |

The notebook's business interpretation reports that the optimized solution reduced the number of waves from **9,707 to 8,189**, increased average workload from **22.17 to 23.40 units**, increased utilization from **88.67% to 93.58%**, reduced average unique locations from **10.68 to 2.07**, and reduced average spatial spread from **889.64 to 8.18**.

---

## Important data limitation

The notebook states that spatial optimization covered:

- **191,583 of 215,192 picking units**
- **89.03% coordinate coverage**
- **23,609 units** had incomplete warehouse coordinates and were excluded from spatial optimization.

The dashboard therefore represents the final optimized coordinate-valid workload. It should not be interpreted as a direct measurement of actual picker travel-time savings.

The notebook specifically notes that actual travel-time or distance savings were **not directly measured**, because route-level movement data was not available.

# Run locally

## 1. Install Python

Python 3.9+ is recommended.

## 2. Install dependencies

Open a terminal in the project folder and run:

```bash
pip install -r requirements.txt
```

## 3. Start Streamlit

Run:

```bash
streamlit run app.py
```

Streamlit will open the dashboard in your browser.

# Deploy on Streamlit Community Cloud

## 1. Create a GitHub repository

Create a new GitHub repository, for example:

```text
warehouse-order-picking-optimization
```

## 2. Upload these files

Upload:

```text
app.py
optimized_wave_summary.csv
optimized_wave_locations.csv
requirements.txt
README.md
```

## 3. Open Streamlit Community Cloud

Go to Streamlit Community Cloud and connect your GitHub account.

## 4. Create the application

Choose:

- Repository: your warehouse optimization repository
- Branch: `main`
- Main file path: `app.py`

Then deploy the application.

## 5. Wait for deployment

Streamlit will install the packages listed in `requirements.txt` and start `app.py`.

# Optimization logic represented by the final results

The final notebook version is **V3.1 Proximity-Constrained Wave Optimization**.

The notebook uses the following important settings:

```text
Target workload = 24 units
Maximum workload = 25 units
Maximum units per location in a wave = 12
Maximum step distance = 50
```

The objective is to organize picking work into geographically concentrated waves while maintaining practical workload limits.

---

# Project interpretation

The final optimization is intended to create:

**Fewer waves**
→ **Higher workload utilization**
→ **Fewer unique locations per wave**
→ **Lower spatial dispersion**
→ **Potentially less picker movement**

However, the project does not directly calculate real picker travel time. Therefore, the dashboard should describe the result as **spatially optimized wave grouping** rather than claiming a measured percentage reduction in walking distance or picking time.

# Troubleshooting

### Error: CSV file not found

Make sure both CSV files are in the same GitHub directory as `app.py`:

```text
app.py
optimized_wave_summary.csv
optimized_wave_locations.csv
```

### Streamlit does not start

Install the dependencies again:

```bash
pip install -r requirements.txt
```

Then run:

```bash
streamlit run app.py
```

### GitHub deployment fails

Check that:

1. `app.py` exists in the selected branch.
2. The two CSV files are uploaded.
3. `requirements.txt` exists.
4. The Streamlit Cloud main file is set to `app.py`.
